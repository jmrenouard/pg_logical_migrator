# Release v1.4.1

## [1.4.1] - 2026-05-13

### Security & Data Integrity 🔒
- **SQL Injection Prevention**: Implemented `sanitize_identifier()` across all DDL operations to ensure safe handling of database, schema, and publication/subscription names.
- **Log redaction**: Added `redact_conninfo()` to automatically scrub passwords from connection strings in logs and reports.
- **Secure File Handling**: Fixed permissions on temporary `pgpass` files (enforced `0o600` immediately upon creation).
- **Safe Shell Execution**: Migrated `execute_shell_command` away from `shell=True` to `shell=False` and introduced `pipe_shell_commands()` for robust `pg_dump | psql` execution.

### Reliability & Correctness 🛠️
- **Pipeline Execution**: Fixed the `post-migration` pipeline execution order to properly sequence termination and final sync steps (Wait sync → Terminate → MatViews → Sequences → Post-data).
- **Session Stability**: Resolved intermittent `psycopg.errors.AdminShutdown` crashes during object auditing by explicitly closing stale destination connection pools immediately following destructive operations (`drop-dest`).
- **Database Connectivity**: Implemented a basic connection pool mechanism (`_conn_txn`, `_conn_auto`) in `PostgresClient` to efficiently reuse connections and prevent exhaustion.
- **Resilience**: Added robust timeouts to database connections (`connect_timeout=10`, `statement_timeout=300000`).
- **Reporting**: Fixed an issue where HTML audit reports incorrectly defaulted to "SUCCESS" by implementing dynamic status calculation.
- **Transactions**: Fixed a missing `conn.commit()` invocation in `execute_query(fetch=False)` for environments without autocommit.
- **Packaging**: Declared missing `src.migrator_components` in `pyproject.toml` packages list to ensure robust PyInstaller builds.
- **Version Tracking**: Replaced fragile regex parsing with direct `__version__` imports in pipelines.

### Code Quality & Maintainability ✨
- **Static Analysis**: Resolved all `mypy` strict type checking errors and `ruff` linting violations across the codebase, resulting in 100% type-hint coverage.
- **Architecture**: Refactored the interactive TUI wizard into a robust MVC pattern (`WizardModel`, `WizardView`, `MigrationWizard`).
- **Refactoring**: Unified the usage of `SchemaFilterMixin`, centralized connection parameter extraction, and consolidated late imports.
- **Dependencies**: Explicitly separated `requirements.txt` from `requirements-dev.txt` for cleaner production deployments.
- **Cleanup**: Removed unused imports (`re`) and differentiated "cleanup" vs "terminate" logical steps (steps 10 and 16).

### Tests 🧪
- **E2E & Integration**: Containerized the E2E and integration test suites using Docker Compose, establishing an isolated test environment (Runner + Database nodes).
- **E2E Stability**: Resolved failures in the `test_full_migration` suite during reverse replication setup (`setup-reverse`) by ensuring deterministic cleanup of forward replication artifacts prior to validation.
- **Environment**: Fixed a critical bug in `setup-reverse` where the source container failed to resolve the destination host (`pg_target`) by implementing a loopback IP auto-detection mechanism (`inet_server_addr()`) similar to forward replication.
- **CI / CD**: Refactored the GitHub Actions workflow to execute tests natively on the runner rather than inside a Docker container, fixing DNS name resolution issues. The CI pipeline now dynamically generates and exports local `MIGRATOR_CONFIG` bridging the Docker test environment with native runner validation.
- **Permissions**: Resolved execution permission blockages (`RESULTS/coverage` root ownership error) emerging from the containerized test runners.
- **Coverage**: Validated that all 290 unit tests pass, maintaining strict coverage enforcement above 70% while improving test reproducibility across environments.
- **Wizard Tests**: Fixed `AttributeError` in wizard integration tests (`test_wizard_commands.py`, `test_wizard_config.py`) by updating `_detect_state` and `_init_config` mocks to align with the new `WizardModel` architecture.
- **Packaging**: Centralized `PYINSTALLER_OPTS` configuration to explicitly adhere to the PyInstaller build requirements enforced in GitHub actions.
